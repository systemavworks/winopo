F2.5 · Maquetación: el trabajo que nadie quiere hacer

Observación de campo (17-nov-2026, de una profesora en activo): muchos preparadores y opositores tienen el temario pendiente de maquetar. El contenido existe en Word, en escaneos o en fotos. Lo que no existe es un documento estudiable: portada, índice paginado, epígrafes numerados, tablas que no se salgan de la página.

El problema, en concreto

  • Word con estilos inconsistentes entre temas, y a veces dentro del mismo tema.
  • Escaneos y fotos: no se pueden buscar, ni copiar, ni adaptar a lectura en móvil.
  • PDF de 900 páginas sin índice útil ni numeración: el opositor no sabe dónde está.
  • Preparadores que pagan la maquetación aparte (40–90 € por tema) o la hacen a mano de noche.

Qué hace Winopo

  • Importa DOCX, Markdown o PDF con texto y lo normaliza a un Markdown propio.
  • Aplica una plantilla por tenant: A4, tipografía, encabezado con tema y versión, pie «página x de y».
  • Genera índice paginado y numera epígrafes de forma automática.
  • Devuelve avisos: imágenes por debajo de 150 ppp, tablas que desbordan, epígrafes sin numerar, enlaces muertos.

Qué no hace, a propósito

  • No es un editor WYSIWYG: un editor es otro producto y otro año de trabajo.
  • No inventa contenido: si el epígrafe no está en el texto, no aparece en el PDF.
  • No permite editar el PDF a mano: se regenera desde la versión del tema.
  • No promete diseño libre por preparador en v1.

Pipeline

DOCX / MD / PDF con texto
        │
        ├─ normalizar ──▶ winopo-md (títulos, listas, tablas, imágenes, citas)
        │
        ├─ validar ────▶ avisos de calidad (ppp, desbordes, numeración, enlaces)
        │
        └─ maquetar ───▶ HTML + CSS de plantilla ──▶ WeasyPrint ──▶ PDF
                                                            │
                                              tema_version + hash_plantilla
                                              (derivado, reproducible)

WeasyPrint (HTML+CSS → PDF) y no LaTeX: menos dependencias, funciona en ARM64 sin dolores y usa el mismo lenguaje de estilos que la web. El maquetador vive en un contenedor aparte para no arrastrar Python al core.

Por qué es una fase y no un extra

Comercial

Hoy se cobra aparte o se hace a mano. Incluirlo en el módulo Base es un argumento concreto frente a Opogestión y compañía, y crea dependencia sana: nadie migra un temario ya maquetado.

Técnico

El PDF maquetado es el derivado que ya necesita F1 y F4. Si se improvisa en F4, se rehace. Hacerlo antes de los tests evita duplicar la plantilla en dos sitios.

Aceptación: un DOCX de 40 páginas produce en menos de 2 minutos un PDF con portada, índice paginado y numeración correcta; y el listado de avisos detecta las 3 tablas desbordadas de un fichero de prueba.
Riesgo honesto: la maquetación perfecta es un pozo sin fondo. El límite está en la plantilla única y en los avisos: se dice qué está mal, no se arregla por arte de magia. Lo que requiera criterio editorial (figuras, tablas complejas) sigue siendo trabajo humano, y eso se puede vender como servicio.

Pendientes que no son código

Estos frenan el lanzamiento igual que un bug, pero no se arreglan con un commit.

Antes de cerrar F0

  • D7 — decidir el responsable del tratamiento y redactar la política definitiva.
  • DNS de winopo.es apuntando al servidor.
  • Comprar vinopo.es como defensa ante el error de tecleo.
  • Registrar el repositorio como privado hasta que haya contrato de cesión firmado.

Antes de cobrar (F5)

  • D9 — precio real del preparador por opositor, con al menos un preparador dispuesto a firmarlo.
  • Búsqueda en OEPM y EUIPO, clase 41 (formación), sin conflictos.
  • Texto de renuncia al desistimiento revisado (art. 103.m TRLGDCU).
  • Contrato de cesión de derechos revisado por abogado.
  • Decidir si el servidor actual (CAX11, ya con otros dos productos) aguanta o se contrata un CAX21 aparte.
Repositorio público: el 17-nov-2026 se publicó systemavworks/winopo. Antes de subir nada se sacaron del repositorio el ID, el hostname y las IP del servidor, que ahora viven en privado/ (ignorado por git). Un repositorio público que anuncia la IP de producción ahorra la mitad del trabajo a quien busque problemas.

Cómo se comprueba lo que digo

Sin fe. Estos comandos, en este orden, dicen si F0 está cerrada o no.

cd core
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew test      # 6 clases, 29 pruebas, 0 fallos
ls build/test-results/test/*.xml | wc -l                        # 6: si sale menos, falta ejecutar algo

cd ../web
npm run typecheck && npm run build                             # React 19 + Next 15

cd ..
make dev && make migrate && make seed                          # stack desde cero
curl -s localhost:8080/healthz                                # {"estado":"ok"}
git ls-files | grep -E '^\.env$|\.pem$|id_rsa' || echo 'sin secretos'
Regla de honestidad: una fase con el código escrito y sin los comandos en verde se marca amarilla, no verde. Un test que no corre está en rojo, aunque el archivo exista.
